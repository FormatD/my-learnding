# 本地模块化系统

采用 Vue 3 + TypeScript、ASP.NET Core 10、PostgreSQL 16。生产前端由同一个 API 服务提供，避免跨站会话与额外公开开发端口。

每个家庭变更在 PostgreSQL 事务内取得家庭 advisory lock，再执行幂等检查、可变对象版本检查、领域命令、审计与命令记录。该方案适合单家庭低并发，后续可缩小到学生锁；不得省略命令唯一约束。

内容发布保存完整不可变快照；学习会话保存 ReleaseId，发布新内容不重解释旧作答。评估更新重放整学生的固定事件序列，写入新世代与对应证据、掌握和日程后，同事务切换学生绑定。旧世代不参与活动计算。

参考设计的所有未来目标仍按 STATUS.md 跟踪；当前没有把模型分数当成经过验证的真实能力概率。

能力测量签名从行为、边界、类型及规范化覆盖要求确定性计算。注册新发布修订时与同一稳定身份的既有不可变定义比较；名称修订允许，签名改变拒绝。编辑器将已发布定义置为只读，提供新增独立能力入口。签名可从导出的完整发布定义重建，当前不以语义模型判断“含义是否相同”。

建库任务的输入显式记录生成时的正式库 ReleaseId，未有正式库时记录空输入。处理时只读取这个快照，不读取排队期间后来发布的内容。旧任务缺失快照不能推断，须重新生成。候选保留原始提案和真实引文，人工接受的定义保存到独立草稿，通过能力稳定身份保留来源和审核链路。

手动题目安排从计划 ReleaseId 选择，后续学生绑定变更不会换题。家长判分上下文读取原始会话题目和该作答最新确认的映射更正版本；提交观察点必须与有效映射一致。预览哈希包含映射版本、当前判分、评估世代和作答数量，确认时检查；首次 Pending 判分可直接提交，但一旦携带预览哈希也必须有效。未知步骤保留未知，不按整题结果推断。

纸质记录与正式作答分开：PendingMapping 及原题草稿均不产生证据。家长必须核对发布题目的原题身份、明确判分依据，再通过预览确认。确认在家庭事务中创建无计划位置的 PaperRecorded 任务、固定版本会话、ParentPaperConfirmed 首次作答、人工判分及 Outbox，并把纸质记录标为 Confirmed。重复确认拒绝，原始记录不可覆盖；后续更正复用普通判分/映射修订。代录使用本次确认时间，不回填不确定的历史练习时间或保持间隔。新原题发布后须绑定包含该题的版本，计划才能安排原题复习；缺少原题时仍显示内容缺口。
