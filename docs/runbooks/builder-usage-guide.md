# 辅助建库使用指南

> 适用版本：V1 开发基线（2026-10-07）  
> 入口：家长登录后 → 左侧导航「✧ 辅助建库」  
> 定位：从教材来源到可审核候选的辅助工具，**不自动发布内容，不替代人工审核**

---

## 一、功能总览

辅助建库是一条 **10 阶段流水线**，将教材原文转化为可被学习系统使用的正式内容。

```
来源导入 → PDF解析 → 候选生成 → 向量索引 → 语义建议 → 人工审核 → 内容草稿 → 映射准备 → 映射建议 → 正式发布
```

| 阶段 | 名称 | 说明 |
|---|---|---|
| 1 | 来源与分段 | 导入 PDF/文本/OCR 教材，本地解析分段 |
| 2 | PDF 解析 | 文本型 PDF 自动提取；扫描件标记 NEEDS_OCR |
| 3 | 候选生成与召回 | 本机模型或模拟从来源抽取能力候选 |
| 4 | 向量索引 | 正式能力库的向量快照，用于相似检索 |
| 5 | 语义建议 | 模型对候选做归并/新建/拒绝/待审判断 |
| 6 | 候选人工审核 | 家长逐项核对，决定接受/关联/拒绝 |
| 7 | 内容草稿 | 接受候选后生成的能力草稿，需补齐题目 |
| 8 | 映射准备 | 为题目/课时/资源准备能力关联建议 |
| 9 | 映射建议与审核 | 模型或手工的映射建议，批量人工审核 |
| 10 | 正式发布 | 整份内容审核后发布为正式版本 |

页面分为三个区域：
- **上半部**：10 阶段标签页，查看每阶段的真实记录
- **中间**：建库总览，5 步进度摘要与整体完成度
- **下半部**：来源导入、候选审核、高级设置

## 二、前置条件

### 2.1 本机模型配置（使用本机模型时）

在 `.local/omlx.json` 中配置：

```json
{
  "Omlx.Endpoint": "http://127.0.0.1:8000/v1",
  "Omlx.Model": "Qwen3.5-9B-MLX-4bit",
  "Omlx.MaxOutputTokens": 4096,
  "Omlx.TimeoutMilliseconds": 600000
}
```

认证密钥存放在 `.local/omlx-api-key.txt`，文件权限须设为仅本人可读写（`chmod 600`）。

**安全约束**：
- 地址只接受 `127.0.0.1`，HTTP 协议
- 不使用代理、不跟随重定向
- 密钥不进入 Git、任务配置、导出或 URL

### 2.2 扫描教材准备（使用 OCR 教材时）

```sh
python3 scripts/prepare_textbook_source.py \
  '/教材绝对路径.pdf' \
  --first 6 --last 18 --page-offset 4 \
  --title '北师大版数学X年级下册·第X单元XXX' \
  --output .local/textbook-workflow
```

输出：
- `pages-ocr.json` — 逐页文字、坐标与识别置信度
- `source-pages/` — 每页一个 JSON 文件
- `manifest.json` — 原 PDF SHA-256、范围及审核状态

## 三、第 1 步：准备并校对来源

页面提供三种导入方式：

### 3.1 导入文本型 PDF

- 点击「选择私有来源文件」上传 PDF
- 限制：10 MB、200 页
- 文本型自动提取；扫描件无文本层会返回 `NEEDS_OCR`
- 全部在本地解析，不发送外部

### 3.2 导入已识别的教材文本

- 选择 `source-pages/` 中的 OCR 结果 JSON 文件
- 填入下方表单供核对，**不会自动保存**
- **必须人工校对**：OCR 会将除号误识别为加减号，竖式和图形顺序可能有误

### 3.3 导入受控文本

- 直接填写「来源标题」和「文本内容」
- 适合手动整理的教材文本
- 点击「保存来源」入库

**保存后**：来源进入家庭私有空间，可在「第 2 步」选择该来源生成候选。

> ⚠️ 保存不代表已校对。扫描教材须核对除号、竖式与阅读顺序。

## 四、第 2 步：选择来源，生成候选

### 4.1 生成方式

| 方式 | 说明 | 适用场景 |
|---|---|---|
| **本机模型** | 调用本地 oMLX 模型（如 Qwen3.5-9B） | 有本机模型环境 |
| **本地模拟** | Mock 流程，不调用真实模型 | 验证流程、开发调试 |
| **手工维护** | 手动创建能力定义 | 不需要 AI 辅助时 |

### 4.2 候选生成流程

1. 选择一个已保存的来源
2. 选择生成方式（本机模型/模拟/手工）
3. 后台领取任务 → 调用模型 → 保存结果
4. 候选状态变为 Pending（待审核）

### 4.3 候选协议约束

每个候选必须包含：
- **名称**：能力名称
- **学科**：当前仅支持 MATH
- **类型**：Procedure / Concept / Application / Representation / Misconception
- **年级范围**：1～12，有序
- **可测行为**：可观察的学习行为描述
- **边界**：能力的适用范围
- **来源片段**：合法 UUID，对应实际输入片段
- **逐字引文**：必须在来源片段中逐字存在

**拒绝条件**：
- 缺字段、多余字段、重复 JSON 字段
- 引文不在实际输入片段中
- 虚构定位、重复片段引用
- 结构合法 ≠ 内容正确，仍须人工审核

### 4.4 固定检索配置

新任务保存 `builder-retrieval/4` 配置：
- **TopK**：默认 10，可设 1～50
- **学科筛选**：只列同已记录学科、同类型正式能力
- **别名优先**：已审核别名完全命中时优先列出
- **融合排序**：关键词 BM25 + 模拟相似 RRF 融合

---

## 五、第 3 步：逐项人工审核

### 5.1 审核上下文

点击候选的「核对此候选」，展示：
- 候选名称、可测行为、边界
- 模型/提示版本、完整结构输出
- 实际引文片段（逐字引用）
- 相近能力定义与支持题目（最多 3 道）
- 其他测量目标的对照题（最多 2 道）

### 5.2 审核操作

| 操作 | 说明 |
|---|---|
| **接受为新草稿** | 创建能力草稿，仍需补充题目和发布 |
| **关联已有能力** | 关联到已发布的正式能力 |
| **拒绝** | 标记为不构成可测能力 |
| **保留 Pending** | 稍后处理，不发布 |

**必须填写审核依据**（1～4000 字），说明本次决定的理由。

### 5.3 版本保护

- 页面固定读取时的家庭版本提交决定
- 其他页面写入后旧版本返回 412
- 当前校正和依据保留，不会被覆盖
- 「重新读取此候选」清空未提交内容，须再次核对
- 已处理的候选不能重复决定（409）

## 六、语义建议（第 5 阶段）

### 6.1 四类语义决定

| 类型 | 说明 |
|---|---|
| **LinkExisting** | 关联候选至一个已有正式能力，需逐字引文 |
| **CreateDraft** | 建议形成独立待审能力 |
| **Reject** | 建议不构成可测能力，说明理由 |
| **NeedsReview** | 信息不足，交给人核对 |

### 6.2 语义任务流程

1. 在候选审核区选择「准备语义任务」
2. 后台冻结候选/来源/库/配置输入
3. 调用本机模型，保存原输出和建议
4. 页面展示模型理由、逐字引用和调用记录
5. 人工决定是否采纳建议

**安全约束**：
- 模型不接收原候选置信分数或已有语义决定
- 结果不能自动接受、发布或更改学生学习
- 结构核对只证明身份和出处，不证明归并语义正确

---

## 七、映射建议（第 8-9 阶段）

### 7.1 映射准备

为题目、课时或资源准备能力关联建议：

| 方式 | 说明 |
|---|---|
| **本机模型建议** | 调用 oMLX 生成映射建议 |
| **本地模拟建议** | Mock 流程验证 |
| **手工维护原映射** | 手动维护关联 |

### 7.2 映射协议

输入捕获：
- 题目：题面、答案、讲解、提示
- 课时：标题
- 资源：标题与纸本说明

输出：
- 每个对象恰好一次 Propose 或 NeedsReview
- Propose 含逐字内容引用、能力身份和修订
- 资源与课时只表示教学覆盖，不产生作答证据

### 7.3 批量审核

在「内容与发布」中选择「准备一批建议」：
1. 选择映射来源草稿
2. 选择对照的正式能力库和版本
3. 查看建议，逐项校正
4. 分批接受或拒绝
5. 接受只生成待审核草稿，发布仍需单独审核

## 八、建库总览与进度

### 8.1 五步进度

页面中间显示 5 步总览：

| 步骤 | 指标 | 说明 |
|---|---|---|
| 1 · 准备来源 | 已保存 N 份 | 来源数量 |
| 2 · 生成候选 | N / M 份来源生成成功 | 成功/总来源数 |
| 3 · 人工审核 | N / M 项已审核 | 已审核/总候选数 |
| 4 · 整理内容 | 已建立 N 份候选草稿 | 草稿数量 |
| 5 · 发布使用 | N 项已审核能力进入可用正式版本 | 已发布数量 |

### 8.2 整体完成度

- 统计当前家庭已保存的来源与本机模型候选
- 显示待审核数、候选草稿数、已进入可用版本数
- 尚未设定全书或单元的应覆盖能力清单时，不计算百分比

### 8.3 当前任务状态

- 显示正在处理或排队的本机模型任务
- 生成成功/失败次数
- 页面每 10 秒自动检查更新
- 模拟任务单独保留，不计入教材建库成果

## 九、高级记录与设置

展开页面底部的「高级记录与设置」区域：

### 9.1 建库预算与名额

| 设置项 | 说明 |
|---|---|
| 每日费用上限（USD） | 按 UTC 日期计算 |
| 单次费用上限（USD） | 单次调用上限 |
| 每日 Token 上限 | 每日用量限制 |
| 单次 Token 上限 | 单次调用限制 |
| 同时处理上限 | 并发调用数 |

- 结果不明的额度跨日保留
- 本地调用不产生外部账单
- 真实用量见调用账本

### 9.2 后台任务与中断保护

- 建库、PDF 解析、学习评估与映射准备保存领取和续期记录
- 处理中断后可接替，旧进程失去领取权时不能提交结果
- 接替仍检查原输入及调用预算

### 9.3 建库调用账本

- 每次调用单独保留，包括修复和失败
- 已开始但未确认的结果不会当成未发生
- 旧任务没有记录时不推算用量
- 支持分页查看和筛选

### 9.4 建库运行记录

- 初次处理失败后最多自动重试三次（等待 2、4、8 秒）
- 持续失败则停止
- 原输入和配置保持固定
- 完成的任务不会重复生成

### 9.5 评测材料

- 点击「下载评测材料」导出来源、候选、任务与尝试记录
- 文件含来源内容和审核资料
- 按私有资料保管

## 十一、完整工作流示例

### 11.1 从教材到正式内容

```
1. 准备教材来源
   └→ 导入 PDF 或 OCR 结果 → 校对文字 → 保存来源

2. 生成候选
   └→ 选择来源 → 选择本机模型 → 后台生成 → 候选变为 Pending

3. 人工审核
   └→ 逐项核对 → 填写依据 → 接受为草稿 / 关联已有 / 拒绝

4. 整理内容
   └→ 在草稿中补充测量题、答案、资源、课时

5. 映射建议（可选）
   └→ 准备映射建议 → 批量审核 → 接受映射

6. 发布使用
   └→ 在「内容与发布」整份审核 → 发布正式版本
   └→ 在「进度与计划」绑定学生 → 发布今日安排
```

### 11.2 扫描教材流程

```
1. 运行 OCR 脚本
   python3 scripts/prepare_textbook_source.py ...

2. 家长登录 → 辅助建库
   └→ 导入已识别的教材文本 → 选择 source-pages 中的文件

3. 核对文字与原页
   └→ 检查除号、竖式、阅读顺序

4. 保存来源

5. 选择来源 → 用本机模型生成候选

6. 逐项审核候选
   └→ 核对原文、能力边界 → 填写依据 → 决定

7. 补齐草稿内容 → 发布
```

## 十二、安全与隐私

| 项目 | 说明 |
|---|---|
| 数据来源 | 全部本地处理，不向外部模型发送（除非配置本机模型） |
| 本机模型 | 仅连接 127.0.0.1，不使用代理/重定向 |
| 密钥管理 | 文件权限 600，不进入 Git/配置/导出 |
| 家庭隔离 | 所有数据按家庭隔离，跨家庭 404 |
| 权限控制 | 孩子 403，普通成员不能代替负责人核对 |
| 导出保护 | 评测材料含私有数据，须妥善保管 |
| 删除清理 | 家庭删除级联清理所有建库记录 |

## 十三、当前限制

| 限制 | 说明 |
|---|---|
| Mock 候选 | 模拟流程不代表模型效果，0 分仅为占位 |
| 学科限制 | 当前仅支持 MATH |
| 向量模型 | 真实向量模型和持久索引尚未完成 |
| 语义质量 | 模型可能产生语义错误（如将除法推断为减法） |
| OCR 准确性 | 除号、竖式、数学符号识别可能有误 |
| 教材范围 | 当前教材为北师大版二年级下册除法，与设计基线的三年级混合运算不同 |
| 正式内容 | 接受候选只建立草稿，仍需补充题目并正式发布 |
| 质量验证 | 独立人工金标准和固定评测集尚未完成 |

## 十四、常见问题

**Q: 候选生成失败怎么办？**  
A: 查看阶段记录中的失败原因。初次失败自动重试 3 次（2/4/8 秒间隔）。持续失败后停止，原输入保留。可在高级设置中查看建库运行记录。

**Q: 可以重新处理已失败的来源吗？**  
A: 可以。同输入同配置复用结果；配置变化创建独立任务。完成的任务不会重复生成。

**Q: 接受候选后会自动发布吗？**  
A: 不会。接受只创建能力草稿，仍需补充测量题、答案、资源与课时，然后在「内容与发布」中整份审核并发布。

**Q: 本机模型调用产生费用吗？**  
A: 本机调用记录为 LocalMeasured，无外部美元账单。Token 记录实际用量，但不产生外部计费。

**Q: 如何处理 OCR 识别错误？**  
A: 导入 OCR 结果后，在表单中人工校对文字再保存。特别注意除号（÷）、竖式数字和阅读顺序。

**Q: 映射建议和候选建议有什么区别？**  
A: 候选建议是从教材来源抽取能力定义；映射建议是为已有题目/课时/资源关联到正式能力。两者独立，分别审核。

**Q: 页面数据多久刷新一次？**  
A: 当前任务状态每 10 秒自动检查。其他数据需手动点击「刷新」或「刷新阶段记录」。
