# 建库操作指南

适用：当前本地“学习系统”（含来源修改与人工确认）。

建库的完整流程是：**核对教材来源 → 生成能力候选 → 人工审核 → 补齐题目与资源 → 审核发布 → 绑定学生 → 发布今日计划**。

模型当前主要提出“能力定义候选”，并不等于已经生成可供孩子作答的完整题库。第一次操作建议只做一页教材、一个能力和几道题，走通全流程后再扩大范围。

辅助建库是一条 **10 阶段流水线**，将教材原文转化为可被学习系统使用的正式内容；它只是辅助工具，**不自动发布内容，不替代人工审核**。

```
来源导入 → PDF解析 → 候选生成 → 向量索引 → 语义建议 → 人工审核 → 内容草稿 → 映射准备 → 映射建议 → 正式发布
```

| 阶段 | 名称 | 说明 |
|---|---|---|
| 1 | 来源与分段 | 导入 PDF/文本/OCR 教材，本地解析分段 |
| 2 | PDF 解析 | 文本型 PDF 自动提取；扫描件标记 NEEDS_OCR |
| 3 | 候选生成与召回 | 本机模型或模拟从来源抽取能力候选 |
| 4 | 向量索引 | 正式能力库的向量快照，用于相似检索 |
| 5 | 语义建议 | 模型对候选做归并/新建/拒绝/待审判断 |
| 6 | 候选人工审核 | 家长逐项核对，决定接受/关联/拒绝 |
| 7 | 内容草稿 | 接受候选后生成的能力草稿，需补齐题目 |
| 8 | 映射准备 | 为题目/课时/资源准备能力关联建议 |
| 9 | 映射建议与审核 | 模型或手工的映射建议，批量人工审核 |
| 10 | 正式发布 | 整份内容审核后发布为正式版本 |

页面分为三个区域：**上半部**是 10 阶段标签页，查看每阶段的真实记录；**中间**是建库总览，含 5 步进度摘要与整体完成度；**下半部**是来源导入、候选审核与高级设置。下文第 1～8 节按操作顺序走查全流程，末尾「功能参考」附录补充协议、设置与限制细节。

## 1. 选定本次教材范围

先写清楚教材版本、年级、上下册、单元、书内页码。本地已导入并关联原图的是北师大版**二年级下册第一单元“除法”**；此前计划的正式试用范围是**三年级上册第一单元“混合运算”**，两者应分别维护。

选“辅助建库”，在顶部“每个阶段的任务与数据”查看已有记录。阶段数字是保存的记录数，不是完成百分比，也不表示全部内容已审核。

## 2. 核对 OCR 文字和分段

入口：**辅助建库 → 1 · 来源与分段 → 找到对应来源 → 校对与确认**。

弹窗左侧是保存的文字及“实际来源片段”，右侧是教材原图。可展开片段、放大图片，并按原教材页选择图片。

逐项检查：

- 数字、加减乘除号、括号、不等号是否正确。
- 竖式是否错行，表格是否丢失行列对应关系。
- 应用题的数量、单位和问题是否完整。
- 图片中的条件是否遗漏，空白答题框是否被误写成答案。
- 分段是否保留了理解这道题所需的上下文。

**发现错误怎么办：**在弹窗左侧“来源校对与确认”点击“修改文字与分段”，直接修改正文，用换行划分段落，并查看“保存后的分段预览”。填写校对说明后点击“保存校对版”，系统会保留原始OCR、创建新来源并沿用原图，然后自动打开新版。

**确认怎么办：**核对新版文字、分段和原图后，填写“复核依据”，点击“确认复核通过”，会显示“已人工复核当前文字与分段”。原文字正确时，也可以直接填写依据并确认，不必先修改。

保存校对版不等于确认通过；确认来源不等于审核候选或发布。旧候选仍引用原来源，修正后要对新校对版另行生成。后续补充原图会使旧确认不再代表当前完整依据，需要重新核对。

“导入已识别的教材文本”可读取现有识别结果，先填入表单供核对，再手动保存。当前网页不直接完成扫描教材的整本 OCR。文本型 PDF 可本地解析，单文件最多10 MB、200页；扫描 PDF 需要另行识别后导入。

**来源没有原图：**在该来源详情右侧展开“补充此来源的教材原图”，选择原教材 PDF、对应页的PNG/JPEG图片，填写PDF页序和书内页码，保存关联。PDF页序从文件第一页算起，可能与印刷页码不同。所选PDF只在本机计算指纹，页图片保存在本地私有库。文本型来源若尚未关联任何页图，页面会用 PDF.js 在浏览器实时渲染 PDF 供翻阅对照；这是临时查看，不算已保存的原图，需要固定证据时仍要按上一步手动关联页图。

只有点击“确认复核通过”才会记录人工确认；查看原图、保存原图关联都不会自动确认。当前支持全文和片段对照，尚无逐段框选定位。

## 3. 用本机模型生成能力候选

入口：**辅助建库 → 第2步“选择来源，生成候选”**。

找到刚核对的来源，点击“用本机模型生成候选”。“验证候选流程”使用模拟流程，不能作为真实教材建库成果。

可在顶部“3 · 候选生成与召回”查看本次任务，也可在“建库总览”查看进度。完成后到下方“逐项审核”处理候选。

失败时先点“查看任务数据”检查错误和处理尝试。修正来源后，应对新来源重新生成；只有页面允许重试的原任务才按原输入重试。不要反复点击生成来绕过未解决的错误。

## 4. 逐项审核能力候选

入口：**逐项审核 → 核对此候选**。

先点“对照原图与来源文字”，再核对候选名称、可测行为和能力边界。能力应描述孩子能独立完成的具体动作。

例如，可测行为可以是“能用竖式计算两位数除以一位数，写出商和余数”；边界可以是“只测实际观察到的竖式计算过程，不包含应用题建模”。不能仅凭最终答案推断孩子完成了所有步骤。

需要参考模型判断时，可在“本机语义建议”点“用本机模型准备语义建议”，查看模型理由及引用。模型建议仍需人工核对；相近能力列表目前含模拟排序，分数不能当成准确率。

填写“本次审核依据”，然后选择：

| 操作 | 适用情况 | 结果 |
| --- | --- | --- |
| 接受为新草稿 | 来源支持该能力，已有库中没有合适的同一能力 | 创建待审能力草稿，还需补题 |
| 关联已有能力 | 可测行为和边界与某个已发布能力一致 | 保存关联及别名，不重复新建能力 |
| 拒绝 | 引用错误、范围不成立，或无法支持该候选 | 保存拒绝及审核依据 |

暂时拿不准就保留“待审核”。审核依据应写实际核对内容，例如“已对照书内第13页原图，确认竖式练习存在；限定为计算过程，不包含分物建模”。

打开/关闭原图不会清除未提交的审核内容；“重新读取此候选”会重新载入记录并清空未提交修改。未保存内容也不保证跨页面或浏览器刷新保留。

## 5. 补齐可学习的内容

接受候选后，点“继续编辑审核草稿”，或到**内容与发布 → 草稿与审核 → 编辑**。

至少补齐：

- **能力：**名称、学科、适用年级、独立可测行为、测量边界。
- **题目：**题干、参考答案、解析、题型、难度，以及实际测量哪个能力。
- **教材目录：**需要按教材安排学习时，填写真实教材/单元/课时，并选择相应原始来源，便于后续追溯原图。
- **资源和课时：**需要讲解或练习安排时，补充可执行的资源说明、预计时长及能力关联。

第一次可先准备一个能力和3～5道人工作答核对过的题；这只是小批操作建议，不是系统统一规定的题量。

映射选择原则：一道普通题整题测量一个主要能力；需要分别观察步骤的题，必须写出真实观察点并采用相应人工判分方式。资源/课时的能力关联表示教学覆盖，不把“看完材料”当成独立答对。

若题目要求列竖式或解释步骤，仅填写数值答案通常不能验证过程，应使用适合人工观察的题型和判分方式。

点击保存草稿。未完成内容可以先保存，但正式发布前必须满足检查要求。

## 6. 需要时使用映射建议

已经在草稿中人工填写好映射时，可直接进入下一步。这一步用于题目较多或需要批量核对关联的情况。

入口：**内容与发布 → 映射建议与批量审核**。

明确选择来源草稿、正式能力库版本和待处理题目/课时/资源，再选择页面提供的处理方式准备建议。使用“手工维护原映射”时，系统只带入已有的明确关联；模拟建议仍需人工核对。

逐项检查原题、答案、能力定义和观察点，校正关联，填写理由后提交接受或拒绝。接受生成的是新的待审草稿，仍需整份审核和发布。

没有正式能力库时，可以先通过上一节的小批内容建立并发布能力库，不必为了走齐所有阶段而强行准备映射任务。

## 7. 审核并发布正式版本

入口：**内容与发布 → 草稿与审核**。

发布前逐题核对答案、解析和能力映射，检查教材适配、资源是否能打开，并可再次使用“对照原图与来源文字”和“查看待审映射”。

确认无误后填写审核备注，点击“审核答案与映射后发布”。如果系统列出错误，按提示补齐、保存并重新审核；通过格式检查不等于题目教学质量已自动确认。

发布后在“已发布版本”看到正式版本。发布内容不可直接修改；需要更正时创建新修订、编辑并重新审核发布。

## 8. 让孩子真正看到题目

**正式发布后，还需要以下三步：**

1. 在“内容与发布”选择正确学生，对目标正式版本点击“绑定当前学生”。
2. 到“进度与计划”，确认学校进度、当天可用时间，生成并核对计划草稿。
3. 发布当天计划，再到“今日学习”检查任务，最后进入孩子模式。

绑定二下“除法”会改变当前学生后续使用的内容版本；如果孩子目前学习三上“混合运算”，应先明确是否用于补弱练习，再选择合适的版本。

## 常见问题

| 现象 | 怎么处理 |
| --- | --- |
| 孩子模式没有题 | 依次检查：草稿是否有测量题、是否已正式发布、学生是否绑定该版本、今天的计划是否已发布 |
| 候选生成成功，但题库仍为空 | 生成的是能力候选；还需接受为草稿并补题、审核发布 |
| 原图没有显示 | 检查来源是否关联页图；新校对来源需要单独关联，不能假定沿用旧来源图片 |
| 向量索引阶段为0 | 当前生产模型索引尚未接入；不阻止先完成小批人工核对流程 |
| 看见模拟任务或模拟分数 | 用于流程验证或辅助排序，不当作真实模型质量证明 |
| 提交提示记录已变化 | 先保留当前输入，再重新读取并核对最新记录，不要盲目反复提交 |
| 老失败任务还在 | 历史记录保留是正常的，核对新任务是否成功即可 |

**第一次建议从现有一份单页来源开始：原图核对 → 生成/核对一个候选 → 接受为草稿 → 补几道题 → 审核发布。确认内容适合当前学生后，再绑定和发布今日计划。**

# 功能参考

以下附录补充流水线各阶段的协议、设置与限制细节，供需要深入核对时查阅；日常操作按上文第 1～8 节走查即可。

## 前置条件

### 本机模型配置（使用本机模型时）

在 `.local/omlx.json` 中配置：

```json
{
  "Omlx.Endpoint": "http://127.0.0.1:8000/v1",
  "Omlx.Model": "Qwen3.5-9B-MLX-4bit",
  "Omlx.MaxOutputTokens": 4096,
  "Omlx.TimeoutMilliseconds": 600000
}
```

认证密钥存放在 `.local/omlx-api-key.txt`，文件权限须设为仅本人可读写（`chmod 600`）。

**安全约束**：地址只接受 `127.0.0.1`、HTTP 协议；不使用代理、不跟随重定向；密钥不进入 Git、任务配置、导出或 URL。

### 扫描教材准备（使用 OCR 教材时）

```sh
python3 scripts/prepare_textbook_source.py \
  '/教材绝对路径.pdf' \
  --first 6 --last 18 --page-offset 4 \
  --title '北师大版数学X年级下册·第X单元XXX' \
  --output .local/textbook-workflow
```

输出 `pages-ocr.json`（逐页文字、坐标与置信度）、`source-pages/`（每页一个 JSON）、`manifest.json`（原 PDF SHA-256、范围及审核状态）。

## 候选协议约束

每个候选必须包含：**名称**、**学科**（当前仅支持 MATH）、**类型**（Procedure / Concept / Application / Representation / Misconception）、**年级范围**（1～12，有序）、**可测行为**、**边界**、**来源片段**（合法 UUID，对应实际输入片段）、**逐字引文**（必须在来源片段中逐字存在）。

**拒绝条件**：缺字段、多余字段、重复 JSON 字段；引文不在实际输入片段中；虚构定位、重复片段引用。结构合法 ≠ 内容正确，仍须人工审核。

固定检索配置：新任务保存 `builder-retrieval/4`，TopK 默认 10（可设 1～50）、学科筛选只列同学科同类型正式能力、已审核别名完全命中时优先、关键词 BM25 + 模拟相似 RRF 融合排序。

## 版本保护

- 页面固定读取时的家庭版本提交决定；其他页面写入后旧版本返回 412。
- 当前校正和依据保留，不会被覆盖。
- 「重新读取此候选」清空未提交内容，须再次核对。
- 已处理的候选不能重复决定（409）。

## 语义建议（第 5 阶段）

四类语义决定：

| 类型 | 说明 |
|---|---|
| **LinkExisting** | 关联候选至一个已有正式能力，需逐字引文 |
| **CreateDraft** | 建议形成独立待审能力 |
| **Reject** | 建议不构成可测能力，说明理由 |
| **NeedsReview** | 信息不足，交给人核对 |

流程：在候选审核区「准备语义任务」→ 后台冻结候选/来源/库/配置输入 → 调用本机模型并保存原输出和建议 → 页面展示模型理由、逐字引用和调用记录 → 人工决定是否采纳。安全约束：模型不接收原候选置信分数或已有语义决定；结果不能自动接受、发布或更改学生学习；结构核对只证明身份和出处，不证明归并语义正确。

## 映射建议（第 8-9 阶段）

为题目、课时或资源准备能力关联建议，方式有本机模型建议、本地模拟建议、手工维护原映射。

映射协议：输入捕获题目（题面、答案、讲解、提示）、课时（标题）、资源（标题与纸本说明）；输出每个对象恰好一次 Propose 或 NeedsReview，Propose 含逐字内容引用、能力身份和修订；资源与课时只表示教学覆盖，不产生作答证据。

批量审核：在「内容与发布」选择「准备一批建议」→ 选择映射来源草稿 → 选择对照的正式能力库和版本 → 逐项校正 → 分批接受或拒绝。接受只生成待审核草稿，发布仍需单独审核。

## 建库总览与进度

页面中间显示 5 步总览：

| 步骤 | 指标 | 说明 |
|---|---|---|
| 1 · 准备来源 | 已保存 N 份 | 来源数量 |
| 2 · 生成候选 | N / M 份来源生成成功 | 成功/总来源数 |
| 3 · 人工审核 | N / M 项已审核 | 已审核/总候选数 |
| 4 · 整理内容 | 已建立 N 份候选草稿 | 草稿数量 |
| 5 · 发布使用 | N 项已审核能力进入可用正式版本 | 已发布数量 |

整体完成度：统计当前家庭已保存的来源与本机模型候选，显示待审核数、候选草稿数、已进入可用版本数；尚未设定全书或单元的应覆盖能力清单时不计算百分比。当前任务状态每 10 秒自动检查，模拟任务单独保留，不计入教材建库成果。

## 高级记录与设置

展开页面底部「高级记录与设置」：

- **建库预算与名额**：每日/单次费用上限（USD，按 UTC 日期）、每日/单次 Token 上限、同时处理上限；结果不明的额度跨日保留；本地调用不产生外部账单；真实用量见调用账本。
- **后台任务与中断保护**：建库、PDF 解析、评估与映射准备保存领取和续期记录；中断后可接替，旧进程失去领取权时不能提交结果；接替仍检查原输入及调用预算。
- **建库调用账本**：每次调用单独保留（含修复和失败），已开始未确认的结果不当成未发生，旧任务无记录时不推算用量，支持分页与筛选。
- **建库运行记录**：初次失败最多自动重试三次（等待 2、4、8 秒），持续失败则停止，原输入和配置保持固定，完成任务不重复生成。
- **评测材料**：「下载评测材料」导出来源、候选、任务与尝试记录；文件含私有数据，须妥善保管。

## 阶段记录查看

页面顶部 10 个阶段标签页，点击展开该阶段的真实记录。每条记录可查看原输入、输出、调用记录、领取与人工审核依据。注意：列表随工作台刷新更新；展开数据以读取时保存记录为准，可手动刷新；未记录的数据不推算补齐；**查看和翻页不会启动模型或改变审核内容**；包含历史失败和模拟流程。

## 完整工作流示例

**从教材到正式内容**：准备来源（导入 PDF/OCR → 校对 → 保存）→ 生成候选（选来源 → 本机模型 → 后台生成 → Pending）→ 人工审核（逐项核对 → 填依据 → 接受/关联/拒绝）→ 整理内容（补测量题、答案、资源、课时）→ 映射建议（可选，准备并批量审核）→ 发布使用（整份审核发布 → 绑定学生 → 发布今日安排）。

**扫描教材**：运行 OCR 脚本 → 导入 `source-pages` 文件 → 核对除号/竖式/阅读顺序 → 保存来源 → 本机模型生成候选 → 逐项审核 → 补齐草稿并发布。

## 常见问答

- **候选生成失败怎么办？** 查看阶段记录中的失败原因；初次失败自动重试 3 次（2/4/8 秒），持续失败后停止，原输入保留，可在高级设置查看运行记录。
- **可以重新处理已失败的来源吗？** 可以。同输入同配置复用结果；配置变化创建独立任务；完成任务不重复生成。
- **接受候选后会自动发布吗？** 不会。接受只创建能力草稿，仍需补题、答案、资源与课时，再到「内容与发布」整份审核发布。
- **本机模型调用产生费用吗？** 本机调用记为 LocalMeasured，无外部美元账单；Token 记录实际用量但不外部计费。
- **如何处理 OCR 识别错误？** 导入后在表单人工校对再保存，特别注意除号（÷）、竖式数字和阅读顺序。
- **映射建议和候选建议有什么区别？** 候选建议从来源抽取能力定义；映射建议为已有题目/课时/资源关联到正式能力。两者独立、分别审核。
- **页面数据多久刷新一次？** 当前任务状态每 10 秒自动检查，其他数据需手动点击刷新。
