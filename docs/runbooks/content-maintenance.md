# 内容维护与更正

适用于本地家庭内容编辑者、发布者和家长。实际权限由服务端检查，孩子不能维护内容。首个负责人有这些角色，后续成员按家庭设置中的实际授权操作。

## 来源与使用范围

导入前由维护者确认来源标题、作者/发布方、版次、取得方式、许可范围和核对日期。`sources/` 是同步的只读参考，不能编辑、移动或删除。需要用于应用的内容，先确认其使用范围，再通过私有来源入口导入；保存来源并不表示得到传播或模型处理许可。

文本导入须有标题、5～100000字正文和非空使用范围。填写能够核对的实际许可依据，不能把默认 `FamilyOnly` 当成自动取得许可的证明。服务只检查该字段非空，不判断授权真实性。相同家庭的相同正文摘要会返回已有来源；重新提交不会改变原来源的标题或许可标记。已有范围不准确时暂停使用，由维护者核对，不通过改正文来规避重复检测。

文本型 PDF 在本地解析，限制10 MB、200页，保留原始私有文件与页码位置；无文本层返回需OCR的状态，不会凭空产生题面。文本片段保留段落位置。图片错题需人工校正文、归因和原题身份。

目前只使用 Mock 建库，用户已安排模型稍后接入。外部 AI 标记默认不允许；即使标记允许，也没有配置真实模型。Mock 验证流程，不证明引用、映射或教学质量。处理失败可以查看运行和尝试历史；仅可重试的原运行由编辑者填写依据重新处理，已产生输出或输入不可恢复时需要修复来源/重新准备，不能重复生成。

## 候选与正式内容审核

在“辅助建库”逐个核对候选引用是否属于实际片段、位置是否正确、可测行为与边界是否完整，再填写实际审核理由。可拒绝、新建草稿或关联已发布能力；关联不会创建新的测量定义，保留别名和审核记录。新建候选草稿通常还缺题目和资源，不能直接作为完整正式单元。

“内容与发布”可以准备20题流程样例或160题/15资源原创单元草稿，也可以从空白草稿维护。二者具有各自的稳定能力身份，历史掌握不能互相继承。原创单元是拟定的三年级上册第一单元范围，具体教材印次、逐题教学适配和人工审核仍待完成。检查表见[160题审核清单](../content/mixed-operations-review.md)，完整快照见[原创目录](../content/mixed-operations-original-v1.json)。不要把题目数量当作独立测量模板数量，也不要把机器算术核对当作人工教学审核。

审核至少逐项检查：

- 目录的教材版本/单元/课时与实际使用教材一致；没有确认的印次、页码不补写为事实。
- 题干、参考答案、解析、难度、覆盖类型、变式组和能力映射一致；资源确实包含可执行讲解/练习。
- 计算题与应用题分开测量；分步观察点及映射权重正确，未观察保持未知。无需测量的内容采用不计证据策略；阅读/听力完成不生成能力掌握证据。
- 前置关系无环；改可测行为、边界、类型或必需覆盖时建立新的能力身份，不能换名称后继承历史概率。
- 来源与使用范围已实际核对；审核人、日期、问题和决定保存于审核清单。系统的整份草稿审核记录不是逐题人工评语的替代品。

保存草稿会撤销旧审核状态，需要重新审核。审核按钮会校验内容完整性和目录来源；校验通过后状态为 Approved。它只表示操作者做出了审核决定，系统不会代替逐题判断。

题目、课时和资源也可在“映射建议与批量审核”选择明确版本，参考本地模拟建议后人工校正。接受只生成待审核草稿，整批失败不部分生效；原始建议和理由保留，发布与学生绑定仍分别确认。见[操作说明](mapping-review.md)与[阶段报告](../content/mapping-review-report.md)，当前未进行正式模型映射质量评测。

## 预览、发布与绑定

发布者审核后获取当前预览，核对错误清单与预览摘要，再确认发布。未审核、草稿已变、版本过期或测量身份冲突会拒绝发布；应重新读取并核对，不能盲目重试。成功后得到不可变发布快照及身份/修订引用。

由家长为学生选择绑定新发布版本。发布本身不改变学生绑定，不重写已领取会话，也不回填历史证据。发布内容不能直接修改；下一次改内容应创建新草稿。题目修订保留同一题目身份的前提是实际身份一致，修订身份要遵循发布校验；改变能力测量定义必须新身份。不要直接操作数据库或修改已发布 Payload 来绕过校验。

讲解资源也记录稳定身份和独立修订。编辑器保存时为资源创建新修订，再重新审核发布；资源说明、时长、链接或能力范围不能覆盖已发布的同一修订。旧快照没有资源修订时保持原样、仍可读取，不由系统猜测或回填版本；一旦同一资源已发布独立修订，后续新发布必须继续记录修订，不能通过清空版本绕过保护。资源修订不自动改变学生绑定、已发布任务或证据。

## 撤回

发现发布版本不适合继续使用时，由发布者填写实际原因并调用撤回接口。当前网页没有撤回按钮，维护者使用下表的接口；角色与家庭范围仍由服务端检查。撤回标记和原因审计保留，没有“删除版本”或“撤回后自动恢复证据”的效果。

撤回阻止新绑定和新会话，既有领取会话与历史作答、证据保留。家长核对当前学生绑定和未来任务，再另行绑定已经审核的替代版本；不能把撤回当成历史错误已更正。已有会话有问题时按实际判分/映射更正处理。

## 历史映射与判分更正

映射错误先在新草稿中修正并审核发布。在“证据与复习”选择该学生的首次作答及目标发布版本，预览旧/新映射，再确认。目标版本必须保留同一道题目稳定身份及题干、答案、题型、难度、变式组；映射更正不能顺带替换原题。该入口目前以“家长核对题目测量目标后更正”作为固定理由；需要详细问题依据时通过接口填写实际理由并保留审核记录。

接口可选择1～100条不同首次作答。确认使用原预览摘要，作答游标或评估世代变化时会拒绝，重新预览后再判断。确认追加更正批次、条目和后台队列；后台整学生回放到新世代后切换活动绑定。原始作答及会话领取内容不改，等待处理结束再查看生效结果。

答案、评分依据或观察步骤错误使用判分预览/更正流程，不能冒用映射更正。未知观察不补造正负证据。能力拆分/合并/替换使用独立人工提案，先发布新能力、审核、预览确认；关系元数据不复制或分摊 Beta、旧证据和复习。

## 接口核对表

完整路径前缀为 `/api/v1`。接口维护需有效家长登录 Cookie；写入还需 `X-Learning-Request: 1`、正确的同源信息和新幂等键。同一请求重试保留原键及完全一致的请求正文。PUT/PATCH、`:publish`、`:decide`、`:correct`、`:adjust` 命令还需当前读取所得家庭 ETag 的 `If-Match`；映射更正 `:confirm` 校验的是专用 previewHash。不要用后台轮询版本掩盖正在编辑的数据过期；发生412重新读取核对。完整实际结构由已登录的本地服务 `/api/v1/openapi.json` 提供。

| 操作 | 方法与路径（省略前缀） | 角色/关键输入 |
|---|---|---|
| 查看草稿和版本 | GET `/content` | Parent 或 ContentEditor；草稿仅编辑者可见 |
| 私有文本来源 | POST `/content/sources` | ContentEditor；title/text/usageScope/allowExternalAI |
| Mock 建库 | POST `/builder/runs` | ContentEditor；sourceId/provider=Mock |
| 候选审核 | POST `/builder/candidates/{id}:decide` | ContentEditor；decision/reason，引用须匹配 |
| 原创单元草稿 | POST `/content/unit-pack` | ContentEditor；不会自动审核或发布 |
| 新建/保存草稿 | POST `/content/drafts` / PUT `/content/drafts/{id}` | ContentEditor；title/catalog |
| 审核草稿 | POST `/content/drafts/{id}:review` | ContentEditor；重新校验 |
| 发布预览 | GET `/content/drafts/{id}/preview` | Publisher；读取hash和errors |
| 发布 | POST `/content/drafts/{id}:publish` | Publisher；previewHash |
| 绑定 | POST `/students/{id}/content/{releaseId}:bind` | Parent；目标版本未撤回 |
| 撤回 | POST `/content/releases/{id}:withdraw` | Publisher；reason必填 |

## 完整内容审核快照

新增审核记录保存审核时的草稿标题、版本、完整内容、摘要、审核者和时间，范围为整份内容（CatalogSnapshot）。页面发布使用显式版本检查；另一页面已经保存新版本时返回DRAFT_CHANGED，须刷新核对，不能直接批准未看到的新内容。可以填写“审核备注（可选）”；实际备注标为UserProvided，没有备注只记录执行审核命令的CommandConfirmation，不伪造逐题意见。

“查看审核记录”可以核对当时题目、答案、关联、课时和资源。保存草稿会撤销审核资格并递增版本，原审核快照保留；重新审核新增记录。发布核对当前完整内容、标题、草稿版本及审核者与记录相符，成功后关联实际ReleaseId；发布失败不写半成品关联。家庭导出和加密备份保留记录，孩子不可读取，其他家庭查询404。

旧发布快照保持原样，不回填缺失审核事实。升级前只有ReviewedBy的待发布草稿需要重新审核；缺少完整记录时返回REVIEW_SNAPSHOT_REQUIRED。旧`:review`命令仍可使用，不增加原请求要求，同样捕获当前完整快照；新POST `/content/drafts/{id}/reviews`要求expectedDraftVersion（正整数），可带reason；GET同路径读取记录，前缀为`/api/v1`。新接口读写需内容维护权限及既有登录/同源/幂等约定。

整份内容审核不是教材逐题专业审查、规范化MappingSet或正式模型质量评测的替代品。直接编辑器与历史映射仍需进一步统一容器；本轮未把旧记录补造成逐项审核。

## 发布映射版本

新发布将有独立修订的题目、课时和资源关联到MappingSetRevision/MappingSetItem，并由ReleaseMappingSet固定本次实际选择。“查看发布映射”逐项显示映射版次、能力关联、覆盖权重与作答证据份额，教学完成不产生作答证据。逐项审核的容器保留人工权重；只在完整内容审核中形成的容器以CatalogDefault明确标注覆盖默认值1，ReviewDecisionId与ContentReviewRecordId严格二选一，不把整份审核伪装为逐项决定。

原对象内容未变、仅能力名称与能力修订变化时，完整内容审核形成新的映射容器版次，固定新的能力修订，原容器和原发布保持不变；完全相同的后续发布复用准确容器。已逐项审核的映射仍要求原冻结能力版本，变动必须有新的对象修订和重新审核。证据份额超过六位小数会拒绝发布，整份事务不留下部分容器、条目或绑定。

旧发布没有关联时为LegacySnapshot，保持原快照；新发布包含未记录修订的旧资源/课时会明确显示UnversionedOwners，不补造修订或审核。现代对象全部准确匹配时为Bound；新记录缺失或与发布不符时为BindingIncomplete。GET `/api/v1/content/releases/{id}/mapping-sets`供内容维护者读取；跨家庭404、孩子403。完整家庭导出和加密备份包含实际容器和绑定。

当前直接编辑器保存会新建对象修订，但提交的内联关联没有人工覆盖字段：此路径再次发布会以默认覆盖权重1生成新容器。若需保留或调整既有人工权重，保存后先使用手工映射维护核对并接受，再审核发布。编辑保存时继承/显式确认旧权重及审核前预览仍待继续开发。L1当前读取已发布内联快照，发布时核对与容器的归因投影；历史映射更正、会话/作答对独立容器的固定引用及所有旧路径统一尚未完成。
