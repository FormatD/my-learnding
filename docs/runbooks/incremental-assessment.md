# 增量计算与不可修改状态快照

IncrementalAssessment是逐作答状态转移实现，独立于Assessment.Replay全量计算。保存的不只是Alpha/Beta：包括题目遇见/24小时重复窗、能力最后遇见、同构组与每日正证据限额、不同题/会话、覆盖、独立结果时序、2/7/30天延迟、诊断通过、迟滞/复核、复习状态及两类历史。Append只接受原稳定序列的严格后缀，旧/重复顺序和跨家庭学生拒绝；计算失败的半成品禁止保存或使用，必须从已提交快照恢复。ReviewOccurrence记录实际作答所重构的历史，不伪造当时已保存的数据。

AssessmentCheckpoint与实际Generation/Student用同家庭学生复合外键关联，保存引擎版本、输入数量、PrefixHash、完整状态Payload与PayloadHash；追加状态唯一键为(GenerationId,InputCount)，数据库拒绝更新；同一活动世代可保留多份严格递增状态。新世代新增可空CalculationMode/ProcessedInputCount/IncrementalBaseGenerationId，旧记录全部保持NULL，不补造历史增量快照。CalculationMode为FullStream初次完整流、IncrementalAppend家长新世代重建仅处理严格后缀、OnlineAppend同一活动世代在线追加、FullStreamChangedPrefix原前缀或配置发生变化后完整重算。ProcessedInputCount是真正执行本批转移数量，不用原累计数量冒充本批工作；增量基线关联原真实世代，不能指向其他学生或自己。

所有入口仍先核对固定学习引用并读取实际学生输入。PrefixHash采用assessment-prefix/3（含实际复习目标确认），包含明确引擎/输入/数学规则版本、时区、实际输入前缀和当前教学记录；前缀核对保留不可修改作答/判分、题目/KC及固定映射引用、会话固定来源、任务类型与复习目标，不把任务完成状态、会话结束状态等可变工作流程字段当作数学输入；不变时从原私有状态恢复。在线消费直接在当前活动世代追加新上下文/证据，旧行ID和全部字段不变，当前掌握/复习投影更新，新增行CreatedAt是实际创建时间；家长明确重建则复制前缀到其固定新目标，重绑新上下文/证据自身ID，OccurredAt仍为真实原作答时间。原状态字节与旧证据不改写。源前缀、判分/映射、时区、规则或教学记录变化时不用旧状态，整学生重新计算；状态摘要损坏明确停止，不静默覆盖。家长填写依据后通过POST /students/{id}/mastery:full-rebuild或页面“从原始记录完整重建”明确从源重新计算，跳过原状态但不跳过来源/映射/规则/权限核对；保留原损坏状态。即使完整输入摘要相同，也实际完整计算并保存新目标世代；普通重建仍可复用。已有普通活动请求时409，不能将其悄悄改为完整重建；先取消原请求。ForceFull在不可修改的原请求描述及应用事件保存，旧未记录字段按原普通模式解释，不回填。教学记录当前全部纳入前缀核对，后来的教学也可能触发保守重算。

新状态、证据/上下文/撤销、活动指针、事件/消费回执与任务/领取终态在原家庭锁和租约围栏结果事务内提交。已有相同完整输入仍复用原世代，不补写不存在的旧状态。Checkpoint.Payload保存算法所需状态与实际证据引用，并非原始作答/教材全文副本；输入事实仍以固定引用源记录为准，PrefixHash也不是Generation.InputHash的另一名称。学生/家庭导出包含私有状态，学生/家庭删除级联清理整个基线链，恢复按最新删除清单处理。

验证：规则56/56，五个固定JSON案例在快照每步恢复后核对独立Beta/日期预期；另核对逐前缀与全量全部语义字段、迟滞/稳定/两次失败/诊断、D0/D2/D7/D30、AT15限额释放、分步/多能力、提示/答案/Pending/重试/NoEvidence、教学/时区和固定随机序列。比较只规范化新建行ID/CreatedAt及集合顺序，同时另验每条Evidence与自身Context/Grading引用，数学/历史字段不忽略；Fork新世代也与全量比较。增量运行不调用Assessment.Replay，不用同一全量方法两次作为一致性证明。

incremental_checkpoint_persistence_acceptance.py在真实临时库验证初次两条完整流、后续只算一条后缀且保留原快照/证据，重复输入不新建，更正释放下游限额、实际撤销、不可修改、明确损坏摘要拒绝且无新结果，以及显式完整源重算恢复和学生删除。incremental_checkpoint_fault_acceptance.py真正终止增量结果提交前的独立进程，旧世代/快照/上下文/证据仍活动且无新结果；实际租约到期后两个消费者竞争，固定目标只处理一条后缀、一份新状态/结果及真实成功领取，旧到期领取保留。更正进程中断、评估消费、后台重建故障、原接口和真实页面另回归；合成案例不是家庭实际学习。

设计§7.1的同一活动世代追加已接入并验证：普通新后缀只新增其自身上下文/证据，原证据不复制。每次真实结果追加不可修改Checkpoint，记录实际InputHash/Cursor/CalculationMode/ProcessedInputCount；Generation中的摘要/游标/计算元数据描述当前投影，历史ConsumerReceipt和AssessmentRebuildResult通过同家庭/学生/世代复合外键指向当时Checkpoint，不把当前摘要冒充旧结果。老状态新增元数据和旧回执关联保持NULL，不回填；旧结果可用实际不可修改AssessmentApplied原负载核对原摘要/游标。旧assessment-prefix/1状态与新摘要配方不兼容时，下一次有变化的输入沿固定新目标完成一次重建，再开始在线追加。相同输入不追加空状态。

实际在线持久验收核对前两条输入随后只追加第三条，任务完成状态变化不引发数学前缀更正；原证据/上下文/状态/回执逐列不变，同构限额与掌握只计一次，重复及旧完成标记缺口修复不重算。受控夹具将已完成任务重新排队，家长已有真实结果在后续追加后重入已有结果分支，仍核对原Checkpoint并保留原字节；更正改变前缀后完整重建和真实撤销。online_assessment_fault_acceptance.py真正终止结果提交前进程，读者可见的世代、掌握/复习、上下文/证据、状态/回执和Outbox各列与提交前相同；实际租约到期后双消费者只追加一条、一个新状态。实际页面刷新依据同世代内容变化加载新上下文，过时响应不能覆盖新响应。

读取/核对仍加载学生完整源记录，DomainEvent序列已成为独立评估消费游标和实际边界证明，见[顺序消费](assessment-consumption.md)；该窗口尚未替代数学源读取，不宣称整个增量事件协议或V1已完成。旧同步兼容入口、事件游标/非评估消费者、真实设备/负载、正式模型/内容和四周试用继续开放。

## 前缀摘要单次流式计算（2026-10-05）

AssessmentPrefixHashes按原assessment-prefix/3的完整JSON字节契约流式计算SHA-256。原状态所属/摘要检查仍先执行；只有原引擎/数学规则和数量相容时才同时计算旧前缀摘要。两路摘要在同一次输入序列化中更新，旧数量边界处单独封闭原teaching尾部；没有完整JSON字符串或完整匿名投影数组。每个输入及教学锚点写完即刷新到摘要流。原前缀/完整摘要、配置/字段顺序/转义、空输入、NULL引用和教学记录均保持原值，不引入新摘要版本、数据库字段或历史回填。原教学锚点仍全部参与摘要，修改历史输入仍改变前缀，后缀变化不改旧前缀。取消会中止计算，不返回部分摘要。

规则案例保留旧完整JSON算法为独立对照，核对不同数量边界、空/非空锚点、时区字符串、中文/Unicode扩展字符/引号/反斜线、可空更正/确认引用、历史及后缀变化，并用单次枚举源验证双摘要只枚举一次。设置PREFIX_HASH_BENCHMARK=1运行tests/acceptance项目，可在同进程对比1万项重复结构输入的原两次完整序列化与新双摘要：实测原19,999项序列化、330,001,136字节托管分配/177.72毫秒，新10,000项、6,966,872字节/82.98毫秒，两个摘要一致。该数值是本机一次合成序列化对比，输入复用相同结构，不是1万条真实持久作答或实体设备端到端负载；不推断p95、跨环境耗时或整学生投影性能。

仍读取完整作答前缀，仍需序列化全部当前前缀及保存完整算法状态；跨连续新作答累计成本尚不是只依赖后缀。本次减少双重序列化和大中间字符串，没有关闭完整源读取、Checkpoint状态存储成本、非评估消费者或V1整体退出条件。

## 恢复与新世代分支的状态成本（2026-10-05）

Resume仍解析完整assessment-incremental/1状态并执行原学生、世代、输入数量、规则及证据引用核对。证据引用使用按实际(ContextId,AttemptId,GradingRevisionId)建立的懒索引，替代每条证据扫描所有上下文；不是仅核对ContextId。范围/版本检查及拒绝理由保持；空证据不建索引。旧状态形状、Snapshot字段/顺序及Freeze字节契约不变。

Fork从原字符串独立恢复后，直接构建其内部规范化Snapshot，再重绑新的上下文/证据/掌握/复习身份和世代，重新执行同一恢复门禁。去掉原Freeze→完整JSON解析、再完整JSON序列化→Resume的中间往返。源状态字符串及调用方原引擎不共享可写对象；新状态继续分配自身持久身份及真实创建时间，追加后与全量重放对照，不能把原行当作新行。私有Snapshot不会暴露给其他调用者。

规则对照保留原Fork序列化路径，其恢复调用共用当前校验，专门比较分支额外往返的语义和分配。STATE_FORK_BENCHMARK=1运行1500项合成流状态：原序列化路径47,416,960字节托管分配/85.48毫秒，直接Snapshot路径6,092,296字节/19.47毫秒；排除新Id/创建时间后全部投影语义一致。该对照未使用旧二次扫描恢复器，不作为旧完整恢复耗时、真实持久输入或端到端p95证明。新测试拒绝错Context/Attempt/Grading及NULL关联，验证源引擎不变、新持久身份和分支继续追加与全量一致。

仍保存完整证据、上下文及两类历史，Checkpoint体积及跨追加累计存储仍未缩减；不能通过删除恢复/追溯需要的内容宣称V1性能完成。源读取和持久状态分离等仍继续。
