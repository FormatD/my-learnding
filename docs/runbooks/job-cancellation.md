# 后台任务取消与明确恢复

家长在证据页可“取消重建”；内容维护者可在映射准备页“取消准备”，或后台任务页“取消任务”。填写1～4000字依据，取消独立保存原任务/输入摘要/轮次/原状态/领取标记及实际成员。POST /background-jobs/{id}:cancel 200返回JobCancellationSummary；已取消重复核对不追加取消事实，已完成或已停止409、其他家庭404、孩子403。重建需Parent，候选建库/PDF解析/映射需ContentEditor。必要的学习结果同步不能取消，明确422并保留原始结果与恢复入口；取消可选重建不删除作答/更正，也不停止必需的结果同步。

取消将BackgroundJob改为Cancelled、撤销领取人和提交权限、清除下次执行。排队任务无执行领取，不能补造取消执行历史；Running取消返回ExecutionStopConfirmed=false，直到执行器退出且保存BackgroundJobCancellationObserved及原JobLeaseAttempt.Cancelled，才证明该次执行已停止。返回true仅指未运行或该任务执行结束，不证明外部提供者物理调用已经终止。进程真正崩溃无法确认停止时保留原Running领取和缺口，不伪造观察记录。页面显示提交已取消、处理停止待确认。

取消与结果完成按同一任务行锁串行：取消先胜，旧领取不能通过完成围栏，未提交候选/映射/评估/证据/活动指针回滚；完成先胜，取消返回409，不撤销已提交结果。取消使用FOR NO KEY UPDATE，兼容结果暂存时的外键读取，避免仅因外键引用等待整个计算。心跳发现领取权消失会取消执行令牌；执行器最终提交还必须检查有效领取，即使运算不响应令牌也不能写结果。取消不是删除，也不把已完成结果退回草稿。

仅显式标记的控制入口使用独立事务与专用幂等锁，绕开长时间家庭工作锁；仍有Cookie/来源/CSRF检查、有效请求标识、同键不同正文409、事务内会话/成员锁与最新权限复查。缓存响应也重新核对任务类型所需权限。控制记录不修改内容的Family.Version；任务状态行锁与当前状态负责取消并发判定。普通领域写入仍采用家庭锁/版本协议。私有审计与Command同取消事务提交，完整家庭导出保留依据；学生取消关联StudentId，学生导出带入studentAudit；隐私删除清理。

每次模型调用/修复的独立预算预留事务在短暂共享任务行锁内核对当前领取有效，撤销后不新增调用事实或额度。权限核对和调用Started事实按取消串行，记录在取消前已Started的调用可能继续物理执行；不得将本地取消当作提供者已结束或免费。已返回调用事实不改写，Started/Cancelled且费用未知的预留与并发名额保留，仍须负责人凭实际提供者结果核对。当前没有外部或付费模型调用。

取消终态不自动恢复；明确填写依据后沿既有人工retry入口开新轮次。重建/映射保存本轮实际授权，原不可修改描述、目标、输入摘要不变；建库在取消状态与原输入/输出/预算门禁下明确新轮次。取消后的建库状态由独立同步最终改为Cancelled，不填CompletedAt；旧轮次取消不会覆盖已经明确恢复的新轮次。旧执行器停止观察按原取消审计的领取/轮次匹配，即使新轮次已排队也不丢旧观察。

验证：job_cancellation_acceptance.py暂停真实Builder在候选已暂存且家庭锁持有时，通过另一进程取消；真实心跳停止、结果回滚、实际停止确认、重复取消、撤销领取拒绝再预留调用、受控未知费用额度保留及家庭删除。受控新轮次夹具验证原取消不拦截显式恢复，不冒充HTTP建库恢复证据。openapi_acceptance.py --cancel-regression实际服务验证持有家庭锁时快速返回、幂等冲突、原依据、无伪造领取、类型/终态/成员/孩子/跨家与缓存撤权；以明确未来队列夹具通过实际重建retry沿原快照/目标完成并导出依据。job-cancellation.spec.ts真实页面验证取消、后台状态、恢复及窄屏，明确未来队列夹具保证操作窗口。原消费/映射/重建、预算/租约/调用崩溃及完整接口另做回归。没有修改数据库模型或补造历史取消。

旧同步重建和映射兼容入口没有后台任务可取消；不能宣称所有旧路径统一后台化。独立增量、事件游标、正式设备负载、提供者联调和四周真实试用继续开放。
