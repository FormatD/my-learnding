# 本地 oMLX 与扫描教材建库

当前入口是“辅助建库”。扫描教材先在本机 OCR，按单页保存来源，选择“用本机模型生成候选”，再逐项核对原页、行为与边界。接受候选只创建待审核草稿；题目、测量支持、映射和正式发布仍需审核，不自动修改孩子已有内容或今日计划。

已核对用户提供的北师大版《数学二年级下册》PDF：109页、无文本层，第一单元“除法”为PDF第6～18页（书内第2～14页）。原PDF保持不变。整本47 MB超过原上传上限；本流程读取本地PDF、准备逐页识别文本，不将整本送至外部服务。

## 准备教材来源

在项目根目录运行：

```sh
python3 scripts/prepare_textbook_source.py '/绝对路径/教材.pdf' --first 6 --last 18 --page-offset 4 --title '北师大版数学二年级下册·第一单元除法' --output .local/textbook-workflow
```

使用系统Swift/PDFKit/Vision，不调用云OCR。输出pages-ocr.json保留逐页文字、坐标与识别置信度，manifest.json保存原PDF SHA-256、范围及Pending审核状态。source-pages目录每个JSON是一页的家庭私有来源；source-input.json是整段汇总，仅供检查。当前推荐按单页调用模型，勿将整单元汇总当作已验证的可靠输入。

家长登录后进入“辅助建库”，在“导入已识别的教材文本”选择source-pages中的一个文件。仅填入下方表单，先核对文字与原页再点“保存来源”；不会自动入库或调用模型。OCR会将除号误识别为加减号，竖式和图形顺序也可能有误，不能把识别置信度当作数学正确性证明。

## 本地配置与处理

私有`.local/omlx.json`指定Omlx.Endpoint、Model、MaxOutputTokens；当前端口8000，模型Qwen3.5-9B-MLX-4bit，输出1536 Token。认证只读`.local/omlx-api-key.txt`，文件须仅本人可读写，密钥不进入Git、任务配置、导出或URL。适配依据[oMLX官方接口](https://github.com/jundot/omlx/blob/main/omlx/server.py)，调用`/v1/chat/completions`，请求JSON响应、关闭思考输出。地址只接受字面127.0.0.1、HTTP、/v1；不使用代理、不跟随重定向。

新任务Provider为LocalOmlx，配置builder-config/4固定模型、地址、输出限额及提示摘要；旧Mock配置JSON形状保持。运行沿用后台领取/提交围栏、角色授权、独立调用账本、严格候选Schema、逐字引文检查与最多一次修复。每个候选限定单片段/单引文；未知结构、改写引文、超时、截断或不同模型响应均拒绝候选提交。输入上限12000字符，完整协议含修复最多120秒。来源AllowExternalAI=false可调用本机适配，但仍禁止未配置的外部提供者。

真实本地Token记录为LocalMeasured，无外部美元账单；缺失Token保留未知，旧模拟LocalNoCharge不改。原USD/外部Token预算仍适用于相应提供者；本地Token不占外部付费额度，家庭并发名额仍受控。不据此声称GPU耗时、电费或整机资源无成本。
