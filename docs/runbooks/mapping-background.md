# 后台映射准备

页面准备模拟建议/手工映射维护使用POST /builder/mapping-preparations，202返回真实排队状态；请求不计算建议、不生成假完成记录。GET同路径列表（最近50批）及/{id}查询进度。页面自动查询本批完成状态，也可刷新、离开后重新打开已完成建议。失败时按具体原因提示；只能对MAPPING_PROCESSING_FAILED、JOB_ATTEMPTS_EXHAUSTED或JOB_REQUESTER_FORBIDDEN填写依据，以POST /{id}:retry人工开新轮次。固定输入、预定RunId、统一Job不改变，旧领取历史保留。原请求人失去权限时，有权限成员可明确核对原输入并人工恢复；本轮恢复人/依据/快照摘要/固定输出/轮次保存在审计，不改原请求人。Worker要求本轮授权匹配且恢复人当前仍有维护权限，缺少授权或权限再次变化必须停止。

MappingPreparation与BackgroundJob、排队审计同领域请求事务写入。保存请求人、实际源草稿及版本/文本摘要、明确选择对象/修订、提交时能力库完整快照及摘要、Provider/Model/PromptVersion及mapping-job/1版本，固定未来RunId；数据库拒绝准备记录更新。家庭内同输入唯一，任务和输出运行标识也唯一。旧完成MappingRun不补造历史准备或领取。若同输入已有旧完成结果，新的真实后台领取可核对并复用该结果；不能说该领取发生在旧结果生成时。

新MappingSuggestions任务使用统一领取/心跳/提交围栏，最多4次执行（包含实际中断）。Worker按冻结快照处理，后续修改草稿或发布新能力库不会替换原输入；冻结能力库撤回、原请求人维护权限撤销、输入/版本不一致必须失败，不能自动绕过。Mock为本地排序，Manual只携带明确原关联；二者不调用外部或付费模型。建议、实际完成MappingRun及审计与任务/领取完成同事务提交；失去领取权后旧进程不能提交。重复处理只核对原结果，不能生成多组建议或自动变更正式映射。

MappingRun仍表示真实完成的建议结果，CompletedAt沿用已有非空时间语义；队列状态由独立准备记录对应的BackgroundJob读取，不填假完成时间。既有同步POST /builder/mapping-runs保留原有接口契约，页面已迁入后台。兼容入口与新准备同输入相遇时使用相同固定RunId，避免两个结果；该旧接口仍同步，尚不能宣称全部映射API路径统一后台化。家长重建页面及设计入口已[后台化](assessment-rebuild.md)；旧同步兼容接口、用户取消和独立增量评估仍开放。

权限：ContentEditor/Publisher可准备、读取、重试本家庭任务；孩子403，其他家庭ID404。全家庭导出包含MappingPreparation的原快照及任务/领取/结果引用，家庭删除级联清除；学生导出不混入家庭级映射输入。恢复最新删除清单继续按实际外键结构闭合。
