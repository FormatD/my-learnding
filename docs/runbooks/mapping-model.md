# 本机模型映射接入

## 当前阶段

已实现 `mapping-model/1` 严格协议、本机传输适配器和独立诊断入口。当前网页的映射准备仍为 Mock/Manual；本阶段尚未将 LocalOmlx 接入 MappingPreparation、持久调用账本或人工批量审核页面，不能把诊断结果当作家庭已保存的映射建议。

输入捕获 Question/Lesson/Resource 的稳定身份、对象修订、可用文字、明确的观察点，以及冻结能力定义和修订。题目含题面、答案、讲解和提示；课时目前只有标题；资源只含标题与纸本说明，尚不读取附件或外部网址。输入不含原 KC 关联、映射角色、份额或题目归因策略，避免照抄旧建议；分步观察点来自明确作者标注，不代表独立人工金标准。8对象/100能力/24000输入字符为明确拒绝边界，不静默裁剪。

每个对象恰好输出一次 Propose 或 NeedsReview。Propose 必须含逐字内容引用，能力身份和修订来自所给库，sourceRefs 指向冻结对象；未知、漏项、重复、改写引文、虚构观察点、错误证据方式/份额、超过六位小数或编造置信度均拒绝。NeedsReview 的 NoEvidence/空条目仅表示没有形成建议，不证明没有关联。资源与课时只表示教学覆盖，不能产生作答证据。结构通过不能证明数学、Primary或覆盖权重准确，全部结果仍待人类审核。

传输仅限127.0.0.1的HTTP /v1，禁止重定向与代理，固定模型、提示摘要、输出上限及总调用期限。初始、教学覆盖补充、全局引用约束以及当前按对象约束的提示/请求结构摘要均保留并可复现。当前输出结构按每个对象固定身份、修订和完整来源引用，并将课时/资源策略固定为NoEvidence、None和零证据份额。未返回/超时不补造用量，截断的真实输出与用量先返回，再由诊断拒绝候选；认证文件须本人可读写。当前传输返回事实，持久化和家庭预算由后续后台接入处理，不应直接用适配器替代生产队列。

## 验证入口

构建 `tests/persistence` 后运行 `python3 tests/mapping_model_protocol_acceptance.py`。使用受控本机HTTP返回，覆盖协议、原提示复现、截断真实用量、缺失用量、固定模型、超时、非私密认证及外部地址拒绝，不调用真实模型、不打开测试数据库。

真实模型诊断需明确设置 `OMLX_MAPPING_SMOKE=1`，运行 `python3 tests/mapping_model_local_acceptance.py`。默认读取私有 `.local/omlx.json`、`.local/omlx-api-key.txt` 和原创除法待审题包；可显式指定 MAPPING_LOCAL_CONFIG/PACK/KEY。程序只选一题、一课时、一资源，以草稿能力库进行隔离诊断，不冒充已发布正式库。原子保存 Started，再保存真实 Returned 或 NoConfirmedResponse；认证内容不进入报告。私有报告在 `.local/textbook-workflow/mapping-model-diagnostics/`，文件600，不提交Git，也不写家庭业务数据。

## 后续完整接入

LocalOmlx需要新版本冻结快照和独立持久调用记录，记录实际开始、返回/停止、配置和输入摘要、用量及验证结果；不能伪造 BuilderRun 来借用现有 BuilderCall 外键。模型等待必须在家庭锁外，短结果事务重新核对租约、请求人内容权限及未撤回的冻结库，保留已有取消和重试历史。家庭并发/未知调用额度需与 Builder 共用真实限制。随后接入待审核建议和批量审核，接受仅生成新草稿，不自动发布；旧Mock/Manual快照和兼容入口保持原语义。独立人工质量集及教材正式审核仍是V1门槛。
