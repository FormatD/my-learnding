# 映射建议与批量人工审核

入口：“内容与发布” → “映射建议与批量审核”。内容编辑者和发布者可使用；孩子不能读取原始建议、答案或执行审核。家长只有Parent角色时不具备内容维护权限。当前支持本地Mock建议和手工维护原映射，未调用外部模型。

## 准备与核对

1. 展开“准备一批建议”，选择“本地模拟建议”或“手工维护原映射”，明确选择来源草稿与未撤回的正式能力库。来源可以是已有发布内容对应的草稿，原草稿不会被修改。
2. 按题目、课时或资源查找并选择对象。列表每页20项，选择跨页保留，每批最多100项。旧资源/课时若没有修订身份，先编辑保存草稿，不能猜测历史版本。
3. 准备建议。运行保存源草稿内容、版本、摘要与能力库发布版本；相同输入不会重复创建。之后修改源草稿或发布新能力库，不会替换旧运行输入。
4. 查看原对象、答案、解析、原映射与相近能力，校正每个关联。模拟分步建议保留已有观察点，不把整题结果拆成猜测的能力证据。
5. 选择本批处理项，分别决定接受或拒绝并填写依据。共同理由可显式应用到选中项；它不能替代实际逐项核对。确认核对范围后提交。
6. 接受项生成新的待审核内容草稿及对象映射修订。一次审核有任何错误，整批没有部分生效。分批继续接受时，新草稿包括同一运行此前已接受的映射，不退回原映射。
7. 查看保存的决定与草稿，继续人工检查完整内容，再通过原发布流程审核、预览、发布。学生绑定由家长另外选择；原始作答、旧会话、已发布计划及历史证据不自动重解释。

手工维护只带入原对象明确记录的能力关联、证据份额与观察步骤，不进行排序，不选择替代能力。原能力不在所选正式库时明确提示，须人工补齐或决定拒绝。旧快照没有覆盖权重，初始值1只是待核对默认值，界面明确提示；审核提交后保存实际覆盖值。运行标记`Provider=Manual`、`Model=None`、`PromptVersion=manual-source/1`，分数为空、相近能力为空；手工和模拟来源不合并去重。两者共用固定输入、人工理由、整批事务、新映射修订及发布保护。

## 映射边界

- 关联固定能力库中的KC及其修订，不只记录可变名称。未发布/其他版本/其他家庭的能力不可冒用。
- 课时和资源关联仅表示教学覆盖，证据份额为零、方式为不计证据。完成资源不是独立正确作答。
- 整题测量只有一个可测能力；前置/上下文不能测量。没有独立动作的综合题采用不计证据，不通过模拟分数绕过。
- 分步测量需要可人工判分题型、明确观察点和正份额。测量份额总和不超过1；覆盖权重单独保存，不能冒充证据份额。份额与覆盖最多六位小数，避免表中舍入与快照不一致。
- 引用只能定位本次冻结对象；不填写虚构页码。原始提案、校正内容、摘要、审核人、日期及依据分别保留。
- 保存草稿可能给未改变的能力生成新的未发布修订。接受时，定义完全相同的能力固定到明确选择的正式库修订；定义本身不同则拒绝，不能静默覆盖名称或测量范围。

人工接受的新对象修订包含完整定义摘要，发布会核对。若同一已接受修订的说明、映射、时长或固定能力版本又被改变，发布拒绝；应保存新的对象修订并重新审核。编辑器正常保存会创建新修订，原审核快照与版本保留。

另一页面有家庭修改时，本页仍提交原读取版本。过期修改被拒绝，当前校正和理由保留；点击“刷新映射审核”显式重新读取并重新选择处理项，不用后台取得的新版本掩盖过期编辑。撤回冻结能力库后不能接受旧建议，但可明确拒绝。权限调整撤销旧登录和缓存回复，需重新登录。

## 处理统计与限制

页面显示待处理、接受、拒绝和校正次数。校正比较实际映射，排序元数据变化和数值等价的小数表示不算映射校正。完整原始/校正摘要仍包含全部提案字段。

该统计不是正确率、教学效果或真实模型评测。当前没有正式人工金标准，EvaluationStatus为NotEvaluated；见[阶段报告](../content/mapping-review-report.md)。新手工工作台经审核生成规范化容器；内容编辑器直接保存和历史映射仍使用原快照路径，本次没有补造其逐项审核记录，也未把所有路径迁入新容器。完整统一映射与真实质量退出条件仍待推进。

完整家庭私有导出和加密数据库备份保留运行、原始建议、决定、映射修订及条目；学生级学习数据不因建议产生证据。家庭删除通过复合外键级联，并由独立删除清单保护旧备份恢复。

## 接口

路径前缀为`/api/v1`，登录/同源/幂等约定沿用[接口手册](api-contract.md)。

| 路径 | 方法与作用 |
|---|---|
| `/builder/mapping-runs` | GET最近50个运行摘要；POST按draftId、libraryReleaseId、owners明确准备本地建议；provider可为Mock（默认）或Manual（只带入原映射），创建201、复用200 |
| `/builder/mapping-runs/{id}` | GET冻结输入、能力库、原始建议、审核决定、映射容器与统计 |
| `/builder/mapping-runs/{id}/suggestions:decide` | POST 1～100项接受/拒绝，逐项reason；接受携带完整correctedProposal，使用原If-Match；整批200，不直接发布 |

映射五个家庭私有表使用复合家庭外键。完整内容审核另保留ContentReviewRecord，详见[内容维护手册](content-maintenance.md)。映射接受后的规范化容器通过新对象修订与发布快照对应，发布检查对象定义及能力修订。该版本仍以已发布快照供L1读取，人工更正历史作答继续走既有预览/确认流程。
