# 计划生成时的评估依据与落后保护

设计v1.1 §13.1要求计划保存当时的评估进度，超过默认30秒的积压只能生成保守草稿。新规则为plan/3；历史plan/2与legacy/unknown不改写。

新PlanRevision保存ProjectionSnapshot及原始JSON的SHA-256。plan-projection/1记录实际家庭/学生、数据库采集时间、当时活动世代/输入摘要/作答序号、独立评估事件序号及原应用记录、实际待处理来源的标识/时间/重试/错误、相关已Failed后台任务及原错误/尝试/恢复轮次、失败来源数量、30秒阈值和是否采用保守安排。作答序号与事件序号分别记录，旧未知边界保持NULL；消费者边界可引用其最后一次实际消费，手工完整重建后的当前世代与此边界不必相同，不混淆两者。

没有积压时使用当前已提交评估；未超过30秒且尚未失败时明确待同步；任何未处理来源超过30秒、实际队列重试耗尽或相关后台评估任务已Failed时进入保守安排。保守草稿保留原已完成、进行中、家长锁定及必做任务；新增任务依据已确认学校进度和家长目标。旧掌握状态、旧到期复习和旧弱项证据不参与新增推荐，学校任务使用SCHOOL_CONSERVATIVE及明确理由。不自动改动当前可执行计划；发布仍需家长确认警告。后台真实追平后重新生成新草稿恢复正常推荐，原保守计划的依据保持原样。

采集时间是来源记录，排除在逻辑输入摘要之外；实际世代/摘要/两种进度/待处理来源/失败状态/保守状态进入输入摘要。相同输入重复生成复用原修订和原采集时间；等待跨过阈值、积压变化或追平会改变输入，不会错误复用原提示。预算/人工调整保留生成时的原依据，不将后来评估进度写回旧计划。

迁移仅增加两个可空字段，不推断历史生成时的评估进度。数据库检查成对NULL或已知摘要；新已知负载验证实际SHA、版本、家庭学生和当时世代/消费边界。保存后拒绝改写/清空、移动所属计划或补造旧未知值；隐私删除允许清理计划。学生及家庭导出包含原PlanRevision字段；页面以普通文字说明当时是否有评估/待同步，不展示内部游标。

验证入口：plan_projection_acceptance.py使用真实临时数据库验证迁移原字段保持、实际消费边界、时间不破坏重复生成、30秒积压/固定任务保留/学校保守任务、真实追平、重试耗尽及实际Failed修复任务、不可修改/旧未知保护与删除。plan_projection_api_acceptance.py在真实隔离API中验证初始未知、真实评估后的边界、受控已耗尽旧式来源、警告确认及导出；受控来源不冒充真实运行三次失败或现代事件。online-assessment.spec.ts检查实际页面的初始无评估说明、同步后重新生成及原计划依据保持。正式设备/负载、独立盘恢复、内容审核/模型和长期试用条件另行验收。
