# 数据结构交接与更新

[数据字典](../data-dictionary.md)和[JSON结构快照](../data/schema.json)来自实际已迁移的 PostgreSQL public 目录；生成过程在可重复读的只读事务中查询表、列、约束、索引和 EF 迁移版本。没有导出任何家庭业务行。应用字段默认值、JSON内部结构及领域规则仍以实际代码为准。

## 本机核对

在项目根目录执行以下命令，使用当前开发库的本地连接。口令如有需要放在私有 `PGPASSFILE`，不要写进命令、文档或版本库。

```sh
PGHOST=127.0.0.1 PGPORT=55432 PGUSER=qianjundeng PGDATABASE=learning \
python3 scripts/schema_dictionary.py --psql /opt/homebrew/opt/postgresql@16/bin/psql --check
```

其他机器使用自身的 PGUSER、PGDATABASE 和 PostgreSQL 客户端路径，省略 `--psql` 即使用 PATH 中的 psql。成功输出表数/迁移数；差异时退出非零，不覆盖文档。连接失败只输出通用错误，避免在日志中暴露连接配置。

## 修改结构之后

1. 修改实体与关系定义，添加 EF 迁移；不得直接编辑已发布的内容快照或同步 `sources/`。
2. 在一次性数据库验证空库迁移与旧库升级，核对原始数据保留、家庭外键、级联删除和唯一性；失败先修复再更新文档。
3. 新增表时在生成脚本的用途清单补充实际业务含义。生成器遇到未说明的新表会退出，不能静默忽略。
4. 从已完整应用当前迁移的数据库运行上述命令并去掉 `--check`，生成两个交接文件。可用 `--output-dir` 指向临时目录进行复核；此参数只选择输出位置，不修改数据库。
5. 检查结构差异与迁移一致，并重新运行 `--check`。提交模型、迁移、字典及必要的导出/删除/恢复适配，不用“文档已生成”替代恢复验证。

当前生成器覆盖 public 普通表、未删除列、表约束和索引，不包含视图、函数、触发器、其他 schema 或用户权限。涉及这些对象的结构调整需另行交接并扩展生成范围，不能假设旧生成器完整覆盖。检查实际数据库的迁移版本不等于证明代码没有尚未生成的模型差异。

常规构建入口 `sh scripts/check.sh` 先完成网页生产构建，再构建服务端静态文件清单和规则验收；避免服务端先读取上一版或构建中间态的网页文件。
