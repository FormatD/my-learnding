# 本地性能测量

记录位置：`local-performance.json`。该报告是一次实测结果，不会随着后续代码变更自动保持有效；报告保存被测服务二进制SHA256及代码提交。重新运行会替换报告，运行失败不能用此前报告声称新版本已通过。

## 复测

本地PostgreSQL需要运行在127.0.0.1:55432；工具使用当前本机用户名，并只创建/删除带 `learning_fault_` 前缀的一次性数据库。需先按README构建服务、前端与 `tests/persistence`，安装PostgreSQL工具及Playwright Chromium。

```sh
RUN_PERFORMANCE_BROWSER=1 CHROMIUM_PATH='/path/to/Chromium' python3 tests/performance_acceptance.py
python3 tests/mastery_snapshot_acceptance.py
```

性能工具自行启动临时端口服务，独立删除清单与导出目录均在临时私有目录；不改现有家庭数据。临时库与服务结束后清理。浏览器账号只在该测试库有效，不写入报告。

## 方法

- 一个家庭有三个测量学生，另一个未测学生仅用于建立已发布样例内容。正式冻结样例包含20题、9个能力；从接口创建和绑定测量学生及学校进度。
- 每学生20个不同日期的非缓存新计划，共60次；验证修订号为1，包含真实规划查询与事务保存。所有60次计入，含第一次执行；不等待模型。
- 每轮为三个学生并发作答。每个能力第一次错误，后续正常答题，实际规则判分并落库，共180次。计时含客户端请求及收到响应，不含领取题目或任务完成。
- 从发出答案开始，以50ms间隔轮询，验证该具体Attempt进入当前证据，并查原错题R1属于同一活动世代，才结束追平计时。因此数字含轮询及HTTP观察开销，是可观察延迟的上界。没有只用旧世代的零积压替代完成检查。
- 学习日期是隔离测试构造；作答时间始终为实际服务器时间，不改成历史作答。24小时内重复正证据仍受抑制、错题R1未推进，不证明2/7/30天保持性。
- 累计历史后发布有任务的今日计划，再读取60次今日接口，验证任务非空且可开始。今日API指标仅为诊断；页面另行测量。
- 孩子模式、1024×1366视窗、模拟75ms延迟和下行10/上行2Mbps。重复加载60次完整文档，计时至今日按钮可用及标题可见，最后实际点击打开题目。登录和进入孩子模式不在计时中；同一浏览器会话保留缓存。记录不是首次无缓存加载性能。
- p95使用 nearest rank：排序后取第 `ceil(0.95*n)` 个值，保存所有原始毫秒样本。接口阈值按设计基线§14.3，不通过时保留报告后以失败退出。浏览器独立断言2秒阈值。

## 证据边界

被测服务为本机Debug构建，数据库和服务均在同一开发机，API为loopback；没有实际平板、家庭Wi-Fi或真实模型。浏览器测量期间同机还运行了短时间核心接口回归，不属于严格控制的独立实验。20题样例不代表100候选上界或正式100–300题规模。未测故障期间p95、四周连续表现、长期可用性或教育效果。本次数据不能关闭完整V1性能及试用退出条件。

`mastery_snapshot_acceptance.py`另外以真实数据库精确重现旧查询顺序的混合状态，再暂停新状态读取、让后台实际提交，验证一个读取快照内仍返回旧能力和待处理，下一次请求看到完整的新能力与零积压。它验证读取一致性，不是性能或实体体验证明。
